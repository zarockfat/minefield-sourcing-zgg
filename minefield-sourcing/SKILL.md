# 跨境大卖拆弹式选品 / Minefield Sourcing

## 这个 skill 解决什么

市面上的选品工具都在回答同一个问题：**这个机会有多大**。

几乎没人回答第二个问题：**这个机会会不会让你被告到倾家荡产**。

一个类目月销百万美金、竞争度低、利润率高、数据漂亮得像教科书 —— 而你备货三十万发到海外仓之后，收到一封外观专利侵权律师函，链接被下架、库存被销毁、账户资金被冻结。这不是运气差，这是选品流程里缺了「专利」这一环。

这个 skill 把专利从「事后审查」提前到「选品第一关」，并且用商品主图直接反查外观专利 —— 不需要专利号，不需要律师，4 秒出结果。

**核心原则：专利不是加减分项，是一票否决项。** 一个 95 分的机会如果踩在有效专利上，它的分数是 0，不是 95。

## 流水线：四站拆弹

### 第 0 站 · 定靶（30 秒）

先问清楚三件事，没问就别开跑，否则后面全是无用功：

1. **打哪个站** — 美国(1) / 英国(2) / 德国(3) / 日本(5) ...（`webSiteId` 一律传**数字字符串**，传 `"US"` 直接报错）
2. **什么品类或方向** — 有具体品类词最好；只有「我想做家居」这种宽泛方向也能跑，走第 1 站的榜单路径
3. **预算与供应链底色** — 决定是打「轻小件快反」还是「高客单长周期」，会改变供给端的筛选阈值

如果用户什么都没给，默认：美国站、Sports & Outdoors、轻小件、预算 5-15 美金区间。

### 第 1 站 · 找信号：需求正在从哪冒出来

目标不是「找到最大的类目」（那是红海），而是**找到增速和竞争还没对齐的那个时间差**。

三条信号源，按可信度排序：

**A. TikTok 侧先行信号（最快，领先 Amazon 3-8 周）**

```
tt_commodity_info_list
  countryRegion: "美国"
  dataPeriod: "last7d"
  orderType: "salesQoqDesc"     ← 销量环比降序，暴增品在这
  size: 30
```

返回的 `salesQoq` 是环比百分比。实战中会看到 `391400.0` 这种数字 —— 这不是 391400%，是**从极低基数启动**的信号，说明该品刚起量。这类信号价值极高，但必须配合第 2 站验证它有没有真实供给承接。

配套看 `powerSellerNumber`（带货达人数）。**达人数 0 但销量暴涨 = 纯自然流量起势，是最干净的信号**；达人数已经几百 = 已经被投流商盯上，窗口在关闭。

**B. Amazon ABA 搜索词排名异动（最硬，但滞后）**

```
amz_aba_research_weekly
  webSiteId: "1"
  ds: "20261031"          ← 该查询周的周六日期，格式 yyyyMMdd
  minSearches: 3000
  maxSearchRank: 200000
  order.field: "searchRank"
  order.desc: false
  size: 15
```

关键字段解读（这是本 skill 最容易被用错的地方）：

| 字段 | 含义 | 怎么用 |
|---|---|---|
| `searches` | 周搜索量 | 需求绝对盘子 |
| `searchRankCv` | 周排名变化（负=上升） | 短期异动，噪声大 |
| `w4RankGrowthRate` | 4 周排名增长率 | **主看这个**，过滤单周噪声 |
| `top3ClickShareRate` | Top3 点击集中度 | >0.5 = 头部垄断，新品难进 |
| `titleDensityExact` | 标题密度 | 高 = 卖家都在抢这个词，红海 |
| `cprExact` | 上首页所需单量 | 广告成本代理指标 |

**判读组合：** 搜索量在涨 + `top3ClickShareRate` < 0.3 + `titleDensityExact` < 25 = 需求在涨但供给没锁死，这才是缺口。反过来，搜索量再大，只要集中度 > 0.5，就是别人的护城河。

用 `amz_aba_research_trends`（`timeGranularity: "M"`）拉 12 个月趋势确认不是一次性事件（节日、网红单条视频）。季节性品类要看同比而非环比。

**C. 榜单侧新品渗透（验证「新人还能不能上桌」）**

```
amz_market_research
  marketplace: "1"
  nodeIdPath: "3760901->15342811"    ← 前缀式路径可模糊匹配父类目
  order.field: "total_units"
  order.desc: true
  newProduct: 6                       ← 看 6 个月内的新品表现
  size: 50
```

看 `newProduct` 相关字段的销量占比。**新品还能吃到份额 = 类目没有固化**，这是最直接的入场可行性证据。

### 第 2 站 · 验供给：这个坑有多深

信号有了，现在看落地成本和竞争结构。

```
amz_market_research
  marketplace: "1"
  nodeIdPath: "<第1站拿到的 catIdPaths>"
  pagesSize: 50
```

| 指标 | 健康区间（轻小件） | 说明 |
|---|---|---|
| `brandCnt` | > 15 | 品牌数太少 = 被垄断 |
| `sellerCnt` | > 20 | 同上 |
| `avgPrice` | $15-45 | 低于 $15 广告打不动 |
| `fbaRatio` | > 0.6 | 低于此说明有大量 FBM 卖家，可能是灰产 |
| `avgRatings` | 200-3000 | 低于 200 说明类目还没成熟；高于 5000 说明老玩家筑墙 |
| `amzRatio` | < 0.4 | Amazon 自营占比高 = 别碰 |

然后落到具体商品，看真实卖家国籍和上架时间：

```
amz_product_selection
  webSiteId: "1"
  nodeIdPaths: ["<path>"]
  month: "202609"              ← 月销量数据必须传月份
  minUnits: 200
  sortField: "spu_sales_last_30d"
  sortOrder: "desc"
  pagesSize: 20
```

重点字段：`bus_cnty_cn`（卖家所属地 —— 中国卖家扎堆说明供应链在我们手上，是好事）、`date_first_available`（上架时间 —— 近 12 个月还能起量的品说明缝隙还在）、`sku_cnt`（变体数 —— 变体多是壁垒）、`selling_price_dig`、`is_a_plus`、`reviews_ratings`。

**判断变量：** 如果 Top20 里超过一半是 12 个月内上架且月销 > 300，这个类目是打开的。如果一个 2021 年的 ASIN 独吞 60% 销量，别进去。

### 第 3 站 · 排雷（本 skill 的核心，绝不能跳）

到这里你大概已经心动了。**现在开始拆弹。**

#### 3.1 用商品主图反查外观专利

这是整套流程里别人做不出来的动作 —— 不需要专利号，拿 Amazon 主图直接搜。

```
patent_image_search_single
  url: "<第2站拿到的 main_image_url>"
  model: 2                    ← 外观专利：1=智能联想，2=搜索此图（用 2）
  patent_type: "D"            ← D=外观设计，U=实用新型
  country: ["US"]
  query_text: "TACD:(yoga mat)"   ← ★ 必填类目词，见下方警告
  limit: 10
```

> **⚠ 实测血的教训一：`query_text` 不是可选项。**
> 只用图片检索，一张瑜伽垫主图匹配出来的 Top1 是「Flexible sheet metal 柔性金属板」（Gaiam 瑜伽垫 → 评分 0.595 → 钢板专利）。纯图像向量检索在跨品类上会产生大量伪命中。
> 加上 `query_text: "TACD:(yoga mat)"` 后，命中数从 **24150 条降到 17 条**，且全部为瑜伽垫相关（瑜伽垫背带、可折叠瑜伽垫、瑜伽垫收纳包）。
> **正确做法：`query_text` 填你品类的核心英文词，`TACD:` 是「标题+摘要+权利要求+说明书」全字段检索前缀。**

> **⚠ 实测血的教训二：检索词要用「专利术语」，不是「电商营销词」。**
> 纳米胶带（nano tape）实测：`TACD:(nano tape)` → **命中 0 条**。因为 "nano tape" 是 Amazon/TikTok 的营销叫法，专利文献里写的是 `adhesive tape`。
> 同一张图换成 `TACD:(adhesive tape)` → 命中 47 条；换成 `TACD:(tape)` → 698 条。
> **对照表（电商词 → 专利检索词）：**
>
> | 电商叫法 | 专利检索词 |
> |---|---|
> | nano tape / 纳米胶 | adhesive tape |
> | shapewear / 塑身衣 | body shaper / undergarment |
> | yoga mat | exercise mat |
> | tummy control | girdle / corset |
> | water bottle | beverage container |
> | pet hair remover | lint roller |
> | phone holder | support bracket |
>
> **规则：命中 0 条时，先怀疑检索词，换更基础的技术名词重试，别急着宣布「无风险」。** 0 命中在专利检索里通常意味着查错了，不意味着安全。

返回字段里 `score` 是相似度（0-1），`loc` 是洛迦诺分类号，`current_assignee` 是当前权利人。**相似度绝对值不能单独作为判据**（噪声大），必须三角验证：

| 判据 | 阈值 | 含义 |
|---|---|---|
| `score` | > 0.50 | 视觉上足够像 |
| `loc` 分类 | 与该品类 LOC 一致 | 同类商品（瑜伽垫=06-11 或 03-01） |
| `title` | 语义上与你的商品同类 | 人眼最后确认 |

**三个同时成立才判为风险项。** 只满足一个或两个，标记为「待人工复核」而不是直接否决 —— 误杀一个好好的机会，和放过一个专利雷，代价一样大。

#### 3.2 摸清头部品牌的专利布局

单个商品撞上专利是偶然，头部品牌在系统性地布专利墙才是结构性风险。

```
patent_query_search
  query_text: "ANCS:(<头部品牌名>) AND TACD:(<品类词>)"
  limit: 20
```

`ANCS` = 申请人/权利人字段。返回 `total_search_result_count` 就是该品牌在这个品类上的专利存量。

**判读：**
- 0-5 条 → 品牌没在布防，安全
- 6-20 条 → 有意识保护，避开其核心设计特征即可
- 20+ 条 → 系统性专利墙，**除非你有明确的差异化设计，否则放弃**

同时用 `patent_semantic_search` 把你的**产品技术描述**（不是关键词，是 200 字以上的方案描述）扔进去，找语义相似的专利。这个能捞到图像检索漏掉的实用新型和发明专利：

```
patent_semantic_search
  text: "<200字以上的技术方案描述，写得越具体越准>"
  country: ["US"]
  relevancy: "70%"
  limit: 20
```

#### 3.3 关键一步：查专利还活着吗

**绝大多数人不知道：大量外观专利已经失效，失效专利可以随便抄。** 这是本流程里最能省钱的判断。

```
patent_legal_status
  patent_number: "<3.1 或 3.2 命中的专利号>"
```

返回 `patent_legal.simple_legal_status`：

| 状态 | 含义 | 行动 |
|---|---|---|
| 有效 / 授权 | 还在保护期 | **否决** |
| 审中 | 尚未授权 | 高风险，专利一旦授权可追溯 |
| 失效 / 期限届满 | 已过期或放弃 | **可自由使用** |
| 驳回 | 未获授权 | 可自由使用 |

实测示例：某专利 `USD646492S` 状态为「失效 / 期限届满」→ 该类设计已进入公有领域。

> 外观设计专利保护期各国不同：美国自授权日起 **15 年**（2013 年 5 月后申请的），中国 **15 年**（2021 年 6 月后），欧盟 **25 年**。看到「失效」才安全，看到「有效」就换设计。

#### 3.4 排雷结论的三种档位

| 档位 | 条件 | 行动建议 |
|---|---|---|
| 🟢 通行 | 无相似专利，或命中的全部失效 | 正常推进 |
| 🟡 改设计 | 有相似但有效的专利，且落在可规避的具体特征上 | 输出「必须避开的 3 个设计特征」清单给工厂 |
| 🔴 否决 | 有效专利 + 相似度 >0.5 + 同类目 + 覆盖核心卖点 | 直接换品，别谈规避 |

### 第 4 站 · 痛点逆向：凭什么你能赢

排雷通过只是「能进场」，不代表「能赢」。差异化的素材来自真实差评。

**TikTok 侧（结构化，最好用）：**

```
tt_commodity_voice_analyze
  commodityId: "<商品ID>"
  countryRegion: "美国"
  size: 10                 ← 最大 10，传 30 会报「超出每页最大数据限制」
```

返回按维度分好组：`好评点` / `吐槽点` / `使用场景` / `时间频率`。每条含 `result`（标签）、`percent`（占比）、`number`（提及数）、`reason`（归因说明）。

**这是全网最好用的痛点数据形态** —— 已经聚类、带占比、带归因，直接可以拿去给工厂。

实测示例（塑身衣）：吐槽点 Top3 是「与描述不符 17%」「可能卷起 11%（腿部易卷边）」「不滚下 11%（腰部下滑）」。这三个就是下一代产品的全部设计输入 —— 卷边和下滚是塑身衣的两个死穴，谁解决谁赢。

**Amazon 侧（原始评论，需自己聚类）：**

```
amz_review_query
  skuId: "<ASIN>"
  webSiteId: "1"
  size: 10                 ← 最大 10
```

用 `voiceScore` 筛 1-2 星的 `orginContent`，人工/AI 聚类出高频抱怨。

**输出要求：** 必须落成**具体的、工厂能执行的设计指令**，不能停在「质量不好」这种废话。

反面例子：「用户反映质量不好」
正面例子：「腰部防滑条宽度增加至 3cm（对应 11% 的下滑投诉）；裤腿口加硅胶防卷边条（对应 11% 的卷边投诉）；在 Listing 主图明确标注实际压缩等级（对应 17% 的描述不符投诉）」

## 评分模型

四项打分，专利项有否决权。

| 维度 | 权重 | 数据来源 | 打分要点 |
|---|---|---|---|
| 需求势能 | 25% | ABA 搜索量、4 周增长率、TikTok 环比 | 在涨且在涨的早期 |
| 供给缝隙 | 25% | 品牌数、卖家数、新品占比、集中度 | 新人能上桌 |
| 利润结构 | 20% | 均价、CPR、变体数、FBA 比例 | 广告打得动 |
| 差异化空间 | 30% | 吐槽点密度与可解决性 | 有明确的、能解决的痛点 |

**专利项不占权重，它是闸门。** 输出格式固定为「原始分 / 100 → 闸门判定 → 最终建议」。

举例：
- 92 分 + 🟢 → 强烈推荐，立即打样
- 92 分 + 🔴 → **0 分，放弃**（这就是本 skill 存在的意义）
- 61 分 + 🟡 → 可做，但必须先改设计，附规避清单

## 输出：选品作战卡

最终产出一份 HTML 作战卡。完整可运行样例见 `examples/battlecard-nano-tape.html`（纳米双面胶带案例，含全部样式），写作规格见 `references/battlecard-spec.md`。必须包含这些区块：

1. **一句话结论** —— 「能做 / 改设计后能做 / 别碰」+ 理由
2. **专利风险仪表盘** —— 🔴🟡🟢 + 命中的专利号、权利人、状态、相似度（这一块要显著，是差异化）
3. **需求曲线** —— ABA 12 个月趋势 + TikTok 环比
4. **供给结构** —— 品牌/卖家集中度、新品占比、价格带
5. **痛点热力图** —— 吐槽点占比条形图 + 对应的设计指令
6. **作战参数** —— 建议定价、首批备货量、必避设计特征清单、差异化卖点、季节节奏

作战卡的定位是「能直接发给工厂和合伙人看的决策文件」，不是数据截图堆砌。

## 常见坑（都是实测踩出来的）

**参数类**

- `webSiteId` 必须是数字字符串（`"1"`），传 `"US"` 报 `PARAM_ERROR`
- `amz_sku_query` 的 ASIN 参数名是 `skuId`，不是 `asin`
- ABA 的 `ds` 要传**查询周的周六**日期
- `tt_*` 和 `tt_expert_*` 的 `countryRegion` 传中文（`"美国"`），不是 `"US"`
- 分页上限：TikTok 系 `size` 最大 30（口碑分析最大 10），`current` > 3 需要「查看全部」权限
- `amz_product_selection` 的月销量筛选（`minUnits` 等）必须同时传 `month`

**数据解读类**

- ABA 的 `searchRankCv` 单周变化噪声极大，看 `w4RankGrowthRate`
- TikTok 的 `salesQoq` 出现六位数是**低基数效应**，不代表真实增长率
- 专利图像检索**必须**配 `query_text` 类目词，否则伪命中率极高
- 专利检索词要用技术术语（`adhesive tape`）不是营销词（`nano tape`），否则 0 命中
- **0 命中不等于安全** —— 先换检索词重试三次再下结论
- 专利 `score` 绝对值不可单独采信，要叠加 LOC 分类 + 标题语义三重验证
- 「失效」的专利可以自由使用 —— 先查法律状态再谈规避，别白白放弃机会
- 品牌专利存量为 0（如 EZlifego）说明该品牌没在布防，但**不代表该品类无专利** —— 小发明人专利照样能告你

**流程类**

- 第 3 站不能跳。跳过专利排雷的选品报告，价值是负的 —— 它会让用户去做一个危险的决定
- 发现 🔴 之后**不要**继续算分数哄用户开心，直接说放弃并给替代方向
- 单个商品撞专利是偶然，头部品牌专利存量才是结构性风险，两个都要查

## 无原生接入时的兜底

如果 OpenBoost 没有注册成原生 MCP 工具，用同目录的 `openboost_mcp.py`：

```bash
export OPENBOOST_KEY="<secret-key>"
python3 -I openboost_mcp.py list                          # 列工具
python3 -I openboost_mcp.py schema patent_image_search_single   # 看入参
python3 -I openboost_mcp.py call amz_aba_research_weekly '{"webSiteId":"1","ds":"20261031","size":15}'
python3 -I openboost_mcp.py info                          # 查套餐余量
```

脚本已处理该服务端的两层序列化、SSE 响应、以及部分专利接口「markdown 文档包 JSON」的包装格式。

**跑之前先 `info` 看余量** —— 这个流程单次完整跑完约消耗 15-25 次调用。
